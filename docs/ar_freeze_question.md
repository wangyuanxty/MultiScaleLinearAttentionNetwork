# 自回归滚动冻结问题 —— 问题陈述

## 1. 设定

**模型**：GDN-2（线性注意力，gated delta rule），三分支多尺度（patch 2/4/8），每分支 2 层，
window `W = 64`，单步输出。

**输入**：64 个连续周期的**归一化容量** `x ∈ R^64`（用训练集 min/max 归一化到 [0,1]）。

**输出**：**一个标量 `z`，不是容量**。

**训练目标**（`train_per_sp.py:69-71`）：

```python
wmean = x.mean()                  # 输入窗口自己的均值
wstd  = x.std()                   # 输入窗口自己的标准差
tgt   = (y - wmean) / wstd        # y 是下一个容量值
loss  = mae(pred, tgt)
```

即模型学的是：**「下一个值比你这个窗口的均值高/低几个标准差」**。

**推理解码**：

```python
y_hat = z * wstd + wmean
```

**这个协议来自 PatchFormer / RUL-Mamba**（pytorch_forecasting 的 `EncoderNormalizer`，
逐编码器序列标准化），我们为「同协议可比」而采用。

---

## 2. 现象

**Teacher forcing（每步喂真值）下一切正常**：
- 轨迹 MAE ≈ 0.0066，AE ≈ 2–3 周期
- 三家（我们 / PatchFormer / RUL-Mamba）表现都正常

**自回归（喂自己的输出）下三家全部冻结**：

```
CALCE，真值从 0.86 掉到 0.32，阈值 0.77（归一化 0.6327）

              最终冻结值      穿越次数
我们            0.826          4/10
PatchFormer     0.860          1/10
RUL-Mamba       0.865          0/10
```

**三家都冻在阈值上方**，PatchFormer 和 RUL-Mamba 在 CALCE 上几乎从不给出 RUL 答案。
（RUL-Mamba：8 个 horizon × 10 seeds = 80 次 rollout，**一次都没穿越**。）

---

## 3. 机制（实测）

解码式 `y = z × σ + μ`，两个因子**都是窗口的函数**，在 AR 下都塌：

```
step      窗口 σ        z        预测值      窗口均值
   0     0.00828    -2.13      0.8546     0.8723
  80     0.00695    -1.17      0.8347     0.8428
 150     0.00298    +0.70      0.8275     0.8254
 250     0.00024    +0.32      0.8260     0.8259    ← 预测值精确等于窗口均值
```

**`σ` 塌 34 倍，`z` 从 −2.13 漂到 +0.32。**

**`z` 是窗口的函数**（同一模型，三种窗口）：

```
真实窗口 (std=0.00841)  →  z = -2.08
自造窗口 (std=0.00510)  →  z = -1.34
常数窗口 (std=0)        →  z ≈ 0     （四个不同水平：-0.03 / +0.38 / -0.17 / -0.37）
```

**常数窗口给出的 `z ≈ 0` 是模型的正确行为**——平窗口里「下一个值 ≈ 均值」本来就是对的。
**它没有退化，它在做对的事。**

**这是自洽的定点**：窗口平 → `z≈0` → 追加的值 ≈ 均值 → 窗口保持平。

---

## 4. 自持条件（解析）

维持匀速下降需要：

```
y_hat - y_last = (W/2)·d + z·σ = -d
→ z = -d(W/2 + 1)/σ
```

对纯斜坡窗口 `σ ≈ d·W/√12`，代入后 **`d` 被消掉**：

```
z_临界 ≈ -(W/2 + 1)·√12/W ≈ -1.73     （W = 64，与衰减速率无关）
```

实测与之一致：`z` 从 −2.13 起（比临界更负 → 窗口离散度先**增大**，实测 0.00828→0.00935 ✓），
约第 40–80 步越过 −1.73（转为衰减 → 离散度**塌陷** ✓）。

---

## 5. 已排除的做法

| 做法 | 结果 |
|---|---|
| **增长窗口**（不丢最老值） | ❌ 更差。PANASONIC：MAE 0.0326→0.1086，穿越 10/10→5/10。原因是长度外推（L 涨到训练长度的 2.5–4 倍） |
| **冻结 σ**（解码用起点的 σ） | ❌ 无效。`z` 照塌，`z×σ_ref` 照样 →0 |
| **加噪声**（回灌值加测量噪声） | ⚠️ 有效但有代价。穿越 2/10→10/10，但 MAE +10%~+87%，且冲过头 |
| **K=32 多步直接预测** | ✅ 有效，但改变了任务定义（不属自回归） |
| **改绝对空间 / 增量目标** | ✅ 有效，但要重训 |

## 6. 要问的问题

**约束**：不重训、不换模型、最好确定性。

**问题**：

> 模型输出 `z = f(x)` 是**在权重里学到的、窗口的函数**——这个 `f` 把窗口的平坦程度编码进去了
> （平窗口 → `z≈0`）。自回归必然把窗口推离训练分布。
>
> **是否存在一个解码侧的变换 `T`，使得**
> 1. **`T` 在训练分布内的窗口上是恒等映射**（即没有改变模型），**且**
> 2. **`T(D(f(·)))` 的自回归不动点不是"常数序列"？**

**我的论证是它不存在**：

- `T` 在真实窗口上恒等 ⟹ `T` 不改行为 ⟹ 冻结照旧
- `T` 能防冻结 ⟹ `T` 在某处改变了输出 ⟹ 不是恒等

**即"等价"与"改变行为"互斥。**

但**如果你认为这个论证有漏洞，或者有反例，请指出**——具体来说：

- 是否可能 `T` 在真实窗口上恒等，**但**在自回归产生的（分布外）窗口上做修正？
  （我上面用"`z` 是窗口的函数"排除了它，但**没有证明 `f` 在分布外的行为不可修正**）
- 是否有已知文献处理过「instance normalization + 自回归 rollout」这个问题？
  （RevIN / `EncoderNormalizer` 一类方法在推理端回流时的正确用法）

## 7. 附：为什么这个现象是领域性的

**PatchFormer 和 RUL-Mamba 用同一个 `EncoderNormalizer`，同样冻结**（本工作实测）。

PatchFormer 的代码里有一段注释掉的替代方案：

```python
target_normalizer=EncoderNormalizer(),
#MultiNormalizer([TorchNormalizer(),TorchNormalizer()]),   # 全局标准化
```

**即他们是从全局标准化刻意改成逐窗口的**（注释写 "normalize by group"），
但论文里没有讨论这个选择在自回归下的后果。

**所以这不是我们独有的实现缺陷，是整套 per-SP 基准协议共有的性质。**
所有报 AE ≈ 1–3 的论文，报的都是 teacher-forced 下的数字。
