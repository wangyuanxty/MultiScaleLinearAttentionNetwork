# 自回归滚动：问题、机制与已排除的做法

> 记录时间 2026-09-15。所有数字均为本工作实测，非文献引用。

---

## 一、问题是什么

论文采用 **per-SP 协议**（PatchFormer / RUL-Mamba 那套）：
每个 (数据集, 起始点 SP, seed) 从零训一个模型，在 SP 之后逐周期评估。
报的核心指标是 **AE = |TRUL − PRUL|**，即"预测的 EOL 穿越点与真实穿越点差几个周期"。

**这个协议是 teacher forcing 的**：每一步的输入窗口都从**真值序列**里切出来，
模型的预测**从不进入下一步的输入**。

**实测（CALCE，10 seeds 均值）**：MAE 0.0066，**AE ≈ 3 周期**，R² 0.995。
同协议下三家（我们 / PatchFormer / RUL-Mamba）表现都在这个量级。

**但一旦改成自回归**（把预测值喂回窗口，SP 之后不再见真值），**三家全部失效**：

| | 最终冻在 | 穿越次数 | AR 下的 AE |
|---|---|---|---|
| 我们 | 0.826 | 4/10 | 99 ~ 128 |
| PatchFormer | 0.860 | 1/10 | 17 ~ 95（n=1） |
| RUL-Mamba | 0.865 | **0/10** | — |

（CALCE 真值从 0.86 掉到 0.32，EOL 阈值归一化后是 0.6327。
RUL-Mamba 在 8 个 horizon × 10 seeds = **80 次 rollout 中一次都没穿越**。）

**所以论文报的 AE ≈ 1–3，是 teacher forcing 撑出来的数字，不能解释为部署能力。**

## 二、机制（实测）

### 2.1 模型输出的是什么

**训练目标**（`train_per_sp.py:69-71`）：

```python
wmean = x.mean()                    # 输入窗口自己的均值
wstd  = x.std()                     # 输入窗口自己的标准差
tgt   = (y - wmean) / wstd          # y = 下一个容量值
```

**模型学的不是容量，是「下一个值比你这个窗口的均值高/低几个标准差」。**

**解码**：`y_hat = z * wstd + wmean`

**这个协议继承自 PatchFormer / RUL-Mamba**（pytorch_forecasting 的 `EncoderNormalizer`），
为「同协议可比」而采用。PatchFormer 的代码里有一段被注释掉的替代方案：

```python
target_normalizer=EncoderNormalizer(),
#MultiNormalizer([TorchNormalizer(),TorchNormalizer()]),   ← 全局标准化，被弃用
```

**即他们是刻意从全局改成逐窗口的**，但论文未讨论这个选择在自回归下的后果。

### 2.2 两个因子在 AR 下同时衰减

```
step      窗口 σ        z        预测值      窗口均值
   0     0.00828    -2.13      0.8546     0.8723
  40     0.00935      —        0.8411     0.8581     ← σ 先【涨】
  80     0.00695    -1.17      0.8347     0.8428
 150     0.00298    +0.70      0.8275     0.8254
 250     0.00024    +0.32      0.8260     0.8259     ← 预测值精确等于窗口均值
```

**`σ` 塌 34 倍，`z` 从 −2.13 漂到 +0.32。**

### 2.3 `z` 是窗口的函数（关键实测）

同一个模型，喂三种窗口：

```
真实窗口 (std=0.00841)  →  z = -2.08
自造窗口 (std=0.00510)  →  z = -1.34
常数窗口 (std=0)        →  z ≈ 0     （四个不同水平：-0.03 / +0.38 / -0.17 / -0.37）
```

**常数窗口给出的 `z≈0` 是模型的正确行为**——平窗口里「下一个值 ≈ 均值」本来就是对的。
**模型没有退化，它在做对的事。**

**推论**：`z → 0` 是"窗口变平"造成的（H1），不是"窗口是自己造的"造成的（H2）。
实测支持 H1：**纯常数窗口（绝不是自造的）同样给出 z≈0。**

### 2.4 自洽定点

```
窗口平  →  z ≈ 0  →  y_hat = 0·σ + μ = μ  →  追加 μ  →  窗口保持平
```

**闭环，自我维持，无外部信息可打断。**

## 三、自持条件（解析）

维持匀速下降（速率 d）需要：

```
y_hat - y_last = (W/2)·d + z·σ = -d
→  z = -d(W/2 + 1)/σ
```

对纯斜坡窗口 `σ ≈ d·W/√12`，代入后 **`d` 被消掉**：

```
z_临界 ≈ -(W/2 + 1)·√12/W ≈ -1.73        （W = 64，与衰减速率无关）
```

```
z 比 -1.73 更负  →  下降维持/加速
z 比 -1.73 更正  →  下降衰减，最终冻结
```

**实测吻合**：`z` 从 −2.13 起（更负 → 窗口离散度先**涨**，实测 0.00828→0.00935 ✓），
约第 40–80 步越过 −1.73（转为衰减 → 离散度**塌陷** ✓）。

## 四、试过并排除的做法

| 做法 | 结果 | 原因 |
|---|---|---|
| **增长窗口**（不丢最老值） | ❌ **更差**。PANASONIC k=50：MAE 0.0326→**0.1086**，穿越 10/10→5/10 | 长度外推（窗口涨到训练长度的 2.5–4 倍） |
| **冻结 σ**（用起点 σ 解码） | ❌ **无效** | `z` 照塌，`z×σ_ref` 照样 →0 |
| **加噪声**（回灌值加测量噪声） | ❌ **净负**（见下） | 改变了输入分布，但没改善预测质量 |
| **确定性变换** | ❌ **逻辑上不可能** | 见第五节 |

### 加噪声的完整结果（CALCE k=50，10 seeds）

```
noise ×     MAE             穿越      AE (周期)      最终值
   0.0   0.01825±0.00371    2/10     36±39         0.6935    ← 基准
   0.5   0.02022±0.00360    4/10     78±58         0.6616
   1.0   0.02503±0.01096    7/10     70±41         0.6162
   2.0   0.02924±0.01511   10/10     37±18         0.4020
   4.0   0.03406±0.01333   10/10     35±29         0.1104
```

**穿越率从 2/10 涨到 10/10，但 AE 没变（36 → 35~37），MAE 劣化 86%。**

**结论：它买到的是"给出答案"，代价是轨迹精度翻倍，而答案的准确度一点没提高。**
**这是净负，不是解。**

> ⚠️ 修正记录：早期只看穿越率时我曾判定"加噪声有效"。
> **把 AE 算出来之后这个结论被推翻。** 这是"必须报 AE"的一次实例。

## 五、为什么"等价的解码侧变换"不可能存在

**约束**：不重训、不换模型。

**"等价"的定义**：变换 `T` 必须在**训练分布内的窗口上恒等**（否则就是在改模型）。

**论证**：

```
T 在真实窗口上恒等  ⟹  T 不改行为  ⟹  冻结照旧
T 能防冻结        ⟹  T 在某处改变了输出  ⟹  不是恒等
```

**即"等价"与"改变行为"互斥。**

**支撑证据**：`z = f(窗口)` 是**权重里学到的映射**——
问题在 `f`（模型），不在 `D`（解码）。`f` 不动，`f(自造窗口)` 就还是 ≈0。

**逐个验证所有候选**：

| 变换 | 在真实窗口上 | 等价？ |
|---|---|---|
| 冻结 σ | 真实窗口的 σ 每步都在变，冻住就改了输出 | ❌ |
| z 加下限 −1.73 | 真实窗口上模型输出 −2.08，被夹到 −1.73 → 改了 | ❌ |
| 加噪声 | 输出带随机性 | ❌ |
| 换绝对空间解码 | 输出语义从 z-score 变成容量 | ❌ |

**这一节是我的论证，不是定理。** 未证明的那一步：
**是否可能存在 `T`，在真实窗口上恒等，但在自回归产生的（分布外）窗口上做修正？**
——我用"`z` 是窗口的函数"排除了它，但**没有证明 `f` 在分布外不可修正**。**这是最可能被推翻的地方。**

## 六、不受这些约束的出路（均需重训或换任务）

| 出路 | 代价 | 状态 |
|---|---|---|
| **改训练目标为绝对容量** `tgt = y` | 重训 | 🔄 **实验中**（见第七节） |
| **改训练目标为增量** `Δ = y_{t+1} − y_t` | 重训 | 未做 |
| **scheduled sampling**（训练时喂自己的输出） | 重训 | 未做 |
| **K=32 多步直接预测** | 换任务定义（非自回归） | checkpoint 现成，AE=16.9 |

## 七、进行中的实验：绝对容量目标

**改动**（`train_per_sp.py`，用 `ABS_TARGET=1` 环境变量开关，默认行为不变）：

```python
tgt = y if ABS_TARGET else (y - wmean) / wstd
```

**推理时解码变成 `y_hat = model(x)`——没有 `×σ` 乘法，冻结机制不存在。**

**已训**：CALCE / SP500 / seed 11 → `checkpoints/per_sp/calce/SP500_seed11_abs.pt`
（于加 `_abs` 后缀之前训练，2026-09-15 已改名归位；改名前的名字 `SP500_seed11.pt`
会被按 `SP500_seed*.pt` 通配加载的脚本当成 z-score 模型读进去）。

**⚠️ 一个要记住的坑**：`train_per_sp.py` 的 `eval_sp()` 里**写死了 z-score 解码**
（`model(cin)*wstd + wmean`），所以它对绝对目标模型打印的 AE=52 / MAE=0.0637 **是错的**，
必须用 `ŷ = model(x)` 重算。现已把绝对目标版隔离：ckpt 加 `_abs` 后缀、
指标写到 `results/per_sp_train_abs.json`，z-score 的 `per_sp_train.json` 不再被碰。

**同理**：PatchFormer 绝对目标版用 `run_pf_abs.py`（复制自 `run_pf_nasa_adapted.py`），
把 `target_normalizer=EncoderNormalizer()` 换成 `TorchNormalizer()`，
并关掉了去重（`if False and any(...)`），输出到 `results_CALCE_ABS_prediction_sl_64/`。
**注意它的"绝对"是全局 z-score**（实测 centre=0.645107 / scale=0.184365，
所有样本的 `target_scale` 逐位相同），不是原始容量；但同样是**窗口无关的固定仿射**，
所以一样消掉了冻结机制。

### 7.1 结果：换了失败模式，没解决问题

**teacher-forced 仍然好**（绝对版略差，符合预期）：

| CALCE SP500 run1 | teacher-forced MAE | R² | AE |
|---|---|---|---|
| PatchFormer z-score | 0.0081 | 0.9930 | 1.0 |
| PatchFormer 绝对 | 0.0126 | 0.9897 | **0** |

**AR rollout 两版全崩，但崩法相反**（同一 run 1，同一个 SP500 槽位，配对）：

```
                  z-score run1 (SP500)       绝对版 run1 (SP500)
k= 25   MAE 0.03863  未穿越       MAE 0.07576  未穿越    (2.0x)
k= 50   MAE 0.02579  未穿越       MAE 0.09528  未穿越    (3.7x)
k= 75   MAE 0.02850  未穿越       MAE 0.10366  未穿越    (3.6x)
k=100   MAE 0.03575  未穿越       MAE 0.12703  未穿越    (3.6x)
```

**⚠️ 更正记录**：这两列最初引用的 z-score 值是
`0.04016 / 0.02575 / 0.02918 / 0.03558`，来自 `src/results/ar_ktable_calce.json`
的 `models.pf` —— 但那个 block 里**每个 k 记录的 `sp` 都是 300**，是一次
`--force-sp 300` 跑出来的，**不是 SP500**。拿它配 SP500 的绝对版就是配错对。
上表是 2026-09-15 用 `src/ar_abs_pf_control.py --` C5 现场重测的 SP500 run1
（只读，未写文件）。方向不变，数字更正。

**CALCE AR 轨迹存档的 provenance 是混的**（实测，见 `ar_abs_pf_control.py` 的 C6）：

| 文件 | 内容 |
|---|---|
| `ar_traj_calce.npz` | 与现场 SP500 rollout **不同**（差 ~4e-3 Ah）——`ar_table_from_traj.py` 读的是这个 |
| `ar_traj_calce__sp500.npz` | 与现场 SP500 rollout **逐位相同**（0.0e+00） |
| `ar_ktable_calce.json` | `models.pf` 是 sp=300 |

三个 tag（ours / pf / rm）在两个 npz 之间也都不是同一次 run。
**引用这张表的任何数字之前必须先确认它出自哪一次跑。**

**绝对版不是"冻"，是"往上飞"**——k=100 的逐步轨迹：

```
step   cycle   pred     true     err
   0     541   0.8966   0.8984  -0.0018     ← 第 1 步是准的
   5     546   0.9150   0.8996  +0.0154
  19     560   0.9606   0.8793  +0.0813
  99     640   1.0579   0.7731  +0.2848     ← 真值在此穿越 0.77
 340     881   1.1297   0.3231  +0.8066
```

**四个 k 的 `argmin` 全部落在发射点本身**：预测值**从未**低于它的第一个值，
单调爬到 1.13 Ah（训练区间上界 `hi = 1.134`），`rise_frac` 0.56–0.61。

`d1 ≈ 1e-06`（第 1 步 = 同周期 teacher-forced 预测），所以不是搭建错误：
**第 1 步准确，之后走正反馈发散。**

**两个失败模式：**

| | 机制 | 结果 |
|---|---|---|
| z-score | `×σ` 随窗口变平而塌陷 | **钉在窗口均值**（不动） |
| 绝对 | 没有 `×σ` 可塌 | 自喂微高值 → 读出"在涨" → **推向天花板** |

### 7.2 到目前为止的结论

**「改绝对目标」不是解，是把失败模式换了个方向**——PF 上 MAE 还差 2–4 倍。

而**我们的**模型绝对版（seed 11）走的是另一条路：下降、穿越、AE 22。
两个模型方向相反，说明**"绝对目标能否救回自回归"取决于模型本身**，
不是归一化协议单独决定的。

**⚠️ 两个方向的样本量都还不够**：PF 绝对版只有 run 1；我们的绝对版只有 seed 11
（且当时是为绕开去重而用的 seed 11，与 z-score 的 10-seed 均值**不配对**）。
我们自己的 seed 1–10 绝对版正在训（`ABS_TARGET=1 --sps 500`，
产出 `SP500_seed{1..10}_abs.pt`），训完才能下判断。

## 八、这个现象的领域性

**PatchFormer 和 RUL-Mamba 用同一个 `EncoderNormalizer`，同样冻结**（本工作实测）。

**所以这不是我们独有的实现缺陷，是整套 per-SP 基准协议共有的性质。**
所有报 AE ≈ 1–3 的论文，报的都是 teacher-forced 下的数字。

**而协议之所以是 teacher-forced 的，很可能正是因为自回归滚不动**——
归一化和协议是一起长出来的，换不掉。
